What is EC2 Security Group?
--> Use Case: 
N/w protocol: TCP, UDP and ICMP(Internet Control Message protocol) are carrier protocol.
Carrier protocol: Carry all traffic on internet from one computer to another.
	Traffic: Web server: HTTP(80) or HTTPS(443)
			email: SMTP(25) or Pop3(110)
			file: SMB(445), NFS(2049)
			DB: mySQL(3306), oracle(1521)
			DNS: DNS(53)
Important things to Do for Security Group:
1. connect your security group to EC2 NIC (	Network interface Card) - compulsory
2. when we create security group while creating EC2: Default rule is:
	outbound rule has: All traffic allowed.
	inbound traffic has: a) if AMI is Windows, then port range is 3389
						 b) if AMI is Linux, then port range is 22
3. When we create security group before creating EC2 instance, and attach it afterwords: Default Rule is:
	outbound traffic has : All traffic
	inbound traffic has: No rule (nothing is allowed)
4. Default Security Group: Both inbound and outbound traffic is Allowed.
		Default security group cant be deleted.
		
Important: What is Statefull Security Group:
--->  Statfull Security allows inbound responses which are requested by its client server. Other than that, it will not allowed any traffic from outside.
	example:client server has send request to destination IP: 2.2.2.2 and that IP is giving response, then it will be allowed by inbound rule though
			it has "No traffic Rule"
		This is due to stateful security group.

EC2 instance Placement Group: day 26
	create EC2 instance:
		under Advance details:
			we finde Placement Group.
	3 Placement Strategy:
		Cluster
		Spread
		Partition:
Main Motive of Placment Group: It enables you to influence how your instances are placed on the underlying hardware.  		
	
	 Clustered Strategy: If we want High Speed between 2 instances:
	 Suppose: we have a AZ ap-south-1	
		     in this AZ: we have 3 racks: rack1, rack2, rack3:
			 you have 6 EC2 instances in rack 2.
			 Every rack has common hardware in it: like networking H/w 
			 So, 2 same EC2 instances are under same rack, there will be  high speed.
				There will be no another h/w interference.
				
	Spread Strategy: If we want high Availability:
			Suppose, we have 2 AZ:
						ap-south-1A and ap-south-1B
						Each AZ contains multiple racks.
						Each rack contains different instance.
			So, if one instance got failed, then other instance will be available. 
				here, spread strategy achieve its goal of High Availability.
	Limitations: in single AZ, we can have maximum 7 EC2 instances.			
				
	Partition Strategy: to achieve High speed and High Availability:
			Suppose, we have a AZ - ap-south-1
			in that zone we have 4 racks - rack1, rack2, rack3 and rack4
				So, here partition will be done for rack1 and rack2 - partition 1 - shares hardware 1
													rack3 and rack4 - partiiton 2 - shares hardware 2
				Meaning, each partition contains 2 racks and both will share same H/W								
			This will achieve the goal of high availability and high speed both.
			
	Limitations while creating Placement Group:
		1. name should be unique
		2. You cant merge placement groups.
		3. One EC2 instance can be placed in only one placement group at a time. it can not be span in multiple placement groups.
		4. You can not launch dedicated host in placement group.

Difference between instance storage and EBS storage:	day 35		
	1. instance storage is temporary(non-persistant) where as EBS is persistent.
	2. Data will be lost if instance stopped in instance storage, where as data is safe even if instance is stopped.
	3. Auto-mount with EC2 instance, where as EBS must be attach and mounted with EC2.
	4. Size limit depends on instance type, where as EBS size is upto 16 TB

Create AWS public Subnet and Private Subnet: day 61	
	AWS VPC 2 tier Architecture:
		Tier 1 (public subnet): web / application tier. Resources here are reachable from the internet.
		Tier 2 (private subnet): database tier. Resources here have no direct internet access.
	Qu.	Why split it this way?
			Your database should never be exposed to the internet. Users talk only to the web tier, 
			and only the web tier talks to the database.
			If the web server is attacked, the database is still protected by network boundaries.
Steps to create Public and Private Subnets:
	1. Create VPC
	2. goto subnets. click on create subnets	
	3. select vpc--> subnet name(public subnet-1)--> select AZ-->ap-south-1A
	4. Do the rest with the same. public-subnet-2 --> AZ--> ap-south-1B
	5. private-subnet-1 -->AZ--> ap-south-1A
	6. private-subnet-2 --> AZ-->ap-south-1B
	Once subnets created. Main route(main-RT) table will be created who is associated with all 4 subnets.
	7. create Internet gateway. attach it with VPC.
	8. Create another route table. (public-RT)
	9. Associate only public-subnet-1 and public-subnet-2 with it.
	10. automatically those 2 subnets will be deassociated from main route Table.
	11. goto public-RT--> Routes--> edit routes--> add route--> add Internet Gateway--> save
	12. Those subnets who is having Internet gateway will appear as public subnets.
	13. those who dont have IG, will remain the private subnets.

Difference between Security Group and Network Access Control List (NACL):
		1. SG is dedicated for particular ec2 instance. NACL is applicable for whole Subnets.
		2. in SG, we cannot deny the rule. in NACL, we can deny specific IP if needed.
		3. SG is Statefull whereas NACL is Stateless.
			Statefull: Outbound rule: Must Allow
					   Inbound rule: No Rule Needed.	
			Stateless: Outbound rule: Must allow
					   Inbound rule: Must allow

AWS Transit Gateway: day 73
	It is a network transit hub that can be used to interconnect with VPC's and with on-premises network.
    it can connect:	
					1. one or more VPC's
					2. one or more VPN connections
					3. one or more AWS direct connect.
					4. one or more transit gateway peering connection.
	its like a centralize system, from single Transit gateway, we can connect to multiple VPC's and their peering connections,
	AWS site-to-site vpns, AWS direct connects. 
Example: If we have 4 VPC and we need to connect with each other:
			We have to create 6 different peering connections.
			So, Transit gateway will resolve this issue:
				Create single transit gateway and peer all VPCs with it.

  5. for step 4 we have to create endpoints for ec2 instance 1. create it.
  6. From server 1 , try ping the other 3 instances. it will not ping as their is no connectivity between VPCs.
  7. goto transit gatway option(VPC)-->Create AWS Transit Gateway. Dont change existing settings.
  8. goto transit gateway Attachment--> create 4 attachments (as we have 4 vpc)
  9. Create transit gateway attachment for all 4 vpc
 10. goto route table-->4 route table will be there.
11. take VPC-1 route table--> Route-->Edit route--> Add all CIDR of remaining 3 vpcs and Save changes.
12. Take vpc -2 route table--> add remaining 3 vpc CIDR to route and save.
13. take vpc-3 route table--> add remaining 3 vpc CIDr to route and save.

Network Load Balancer: day 100
	Best for TCP traffic where extreme performance is required.
	Operating at connection level (layer 4) (application LB works on level 7)
	Capable of handling millions of requests per second while maintaining ultra low latency.

Difference in application BL and Network BL:
1. Supported protocol:
				Application LB: HTTP, HTTPS, gRPC
				Network LB: TCP, UDP, TLS
2. load Balancer type:
			physical layer
			Data link layer
			Network layer
			Transport layer
			Session layer
			presentation Layer
			Application layer --> Application LB comes in picture.
	Network Balancer LB:
			physical layer
			Data link layer
			Network layer
			Transport layer --> Network  LB comes in picture.
3. idle Connection time out :
				Application LB : Yes
				Network LB: No
4. Cookies: 
		Application LB: Yes
		Network LB: yes
5. Path based routing and Host based routing:
			Application LB: Yes
			Network LB: No
6. WebSocket Support: 
		Application LB: Yes (two way communication between users and server)
		Network LB: yes
7. Static IP Suported:
			Application LB: No
			Network LB: Yes
